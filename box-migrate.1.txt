.TH BOX-MIGRATE 1 "November 2026" "Box-Migrate 0.8.6" "User Commands" .SH NAME box-migrate - migrate packages, repositories, and caches between Toolbox containers .SH SYNOPSIS .B box-migrate .I SOURCE DESTINATION .RI [ OPTIONS ] .SH DESCRIPTION .B box-migrate migrates manually installed packages from an existing Linux Toolbox container to a newly created destination container.

The destination is created using the specified distribution and release. Box-Migrate identifies the source package manager, exports its manually installed package list, compares it against packages already installed in the destination, and installs packages not already present.

Repository configuration, GPG keys, and local package caches can also be transferred. Repository and cache migration are enabled by default and can be disabled independently.

The source container is not intentionally modified. The destination is created as a separate container. .SH OPTIONS .SS Destination .TP .BR -d ", " --distro " " DISTRO Specify the distribution for the destination container. This option is required. .TP .BR -r ", " --release " " RELEASE Specify the distribution release for the destination container. This option is required. .SS Migration .TP .BR -n ", " --dry-run Run in dry-run mode. Source package, repository, and cache data are still exported, but the destination is not created and packages are not installed. Package comparison uses an empty destination package list, so the displayed package count is not a prediction of the final installation count. .TP .BR -R ", " --repos Enable migration of repository configuration and GPG keys. This is the default. .TP .B --no-repos Disable repository configuration and GPG key migration. .TP .BR -C ", " --cache Enable migration of local package caches. This is the default. .TP .B --no-cache Disable local package cache migration. .SS General .TP .BR -h ", " --help Display the usage information and exit. .SH EXAMPLES .TP .B Migrate Fedora 44 to Fedora 45 .nf box-migrate f44 f45 -d fedora -r 45 .fi .TP .B Preview a migration .nf box-migrate f44 f45 -d fedora -r 45 --dry-run .fi .TP .B Skip repository migration .nf box-migrate f44 f45 -d fedora -r 45 --no-repos .fi .TP .B Skip package cache migration .nf box-migrate f44 f45 -d fedora -r 45 --no-cache .fi .TP .B Skip both repositories and caches .nf box-migrate f44 f45 -d fedora -r 45 --no-repos --no-cache .fi .SH SUPPORTED DISTRIBUTIONS The source and destination must use compatible package manager families. .TP .B DNF Fedora, RHEL, CentOS, Rocky Linux, and AlmaLinux. .TP .B APT Debian and Ubuntu. .TP .B Pacman Arch Linux and Manjaro. .PP Cross-family package migration is not supported. Both containers must use the same package manager. .SH MIGRATION DETAILS .SS Packages The source package list is obtained using the package manager's manually installed package records. Packages already installed in the destination are excluded from the installation list. .PP Package availability depends on the destination distribution and its configured repositories. Packages that are unavailable or incompatible may not be installed. .SS Repositories and GPG keys When repository migration is enabled, repository configuration and associated key files are archived from the source and extracted into the destination. .PP Repository definitions are not guaranteed to be compatible with the destination release. Review imported repository files and their signing keys before using the destination container. The current implementation does not perform comprehensive repository URL sanitization. .SS Package caches When cache migration is enabled, locally cached package files are archived from the source and extracted into the destination. Cached files are not guaranteed to be usable by the destination package manager or compatible with its release. .SH FILES .TP .I ~/.local/state/box-migrate-SOURCE-to-DESTINATION/ Working directory containing exported package lists, repository archives, package caches, and migration reports. .PP If a working directory with the same name already exists, a numbered suffix is added. .PP Important generated files include: .TP .I packages.txt List of packages selected for migration. .TP .I report.txt Package installation output, when an installation is attempted. .TP .I special-cases.txt Summary of detected missing packages and installation issues. .TP .I repositories.tar.gz Exported repository configuration and key archive. .TP .I package-cache.tar.gz Exported local package cache archive. .SH REQUIREMENTS .B box-migrate requires: .IP (bu 2 Toolbox. .IP (bu 2 Podman. .IP (bu 2 Bash. .IP (bu 2 A working source Toolbox container. .PP The destination container name must not already exist. .SH EXIT STATUS .TP .B 0 The script completed successfully. .TP .B Non-zero An error occurred during argument validation, container inspection, creation, package installation, or another operation. .PP A non-zero exit status may occur after the destination container has already been created. Inspect the migration logs and container state before retrying. .SH NOTES The source container is retained after migration. Box-Migrate does not remove or replace it. .PP The destination may be created successfully even if some packages are unavailable or incompatible. Review the installation report and special-cases report after migration. .PP Dry-run mode does not create the destination or install packages. It still creates a working directory and exports data from the source. .PP Repository and GPG key archives should be reviewed before being trusted in the destination. .SH SEE ALSO .BR toolbox (1), .BR podman (1), .BR dnf (8), .BR apt (8), .BR pacman (8)
